How large language models work

LLMs are next-token predictors — they learn patterns from text and generate one token at a time.

Training

  • Text is processed through a transformer network
  • Weights are tuned to capture grammar, facts, and reasoning
  • The result is a fixed set of weights — an 8B model is ~16 GB in full precision

Inference (what we run)

  • A prompt is split into tokens
  • The model predicts the next token from everything before it
  • Repeats until done; temperature and top-p shape the output
Why this matters: A 7B model compressed to 4-bit runs in ~5 GB of memory on a standard laptop. For most tasks, the quality difference versus full precision is imperceptible — which makes local AI practical today.

Why bring AI in-house

Now that a compressed model fits on a laptop, consider what that enables: your data never leaves the building, and costs become predictable.

  • Data sovereignty — sensitive information stays inside your network
  • Predictable cost — no per-token billing; invest in hardware once
  • Reliability — inference runs locally with no vendor dependency
  • Adaptability — models can be tuned to your domain via RAG and fine-tuning
The enabler: Open tooling like ggml and the GGUF format let standard laptops run capable models — no specialized GPU required.

Choosing the right model for the job

Lightweight (3B–7B)

Fast and efficient

  • Memory: 4–8 GB
  • Classification, summarization, drafting
  • Comfortable on CPU and edge devices

General purpose (8B–12B)

The everyday workhorse

  • Memory: 8–16 GB
  • Coding, RAG, and document analysis
  • Strong function-calling support

Large / MoE (24B+)

For harder problems

  • Memory: 24 GB+ VRAM
  • Complex reasoning and agent orchestration
  • Activates only part of the network per task

Qwen3 27B: strong results without a data center

A mixture-of-experts model: of 35B parameters, only 27B are active at a time — performs like a much larger model while staying efficient.

How mixture-of-experts works

  • Specialized sub-networks, not one monolithic block
  • A router picks the relevant experts for each token
  • ~70% of the compute cost of a dense 27B model

Running it locally

  • Memory: ~18 GB (4-bit) — comfortable on a MacBook Pro M4 Pro
  • Ollama: ollama run qwen3:27b
  • MLX: native support on Apple Silicon via mlx-lm
Qwen3 27B reaches the level of dense 70B models on benchmarks using 60% less memory.

Gemma 4: long context for real documents

Google's open model, from the same lineage as Gemini. A 128K context window is a game-changer for document-heavy workflows.

What stands out

  • Two sizes: dense 9B and 27B MoE
  • Distilled from Gemini 2.0
  • 128K context — enough for entire codebases

Running it locally

  • Ollama: ollama run gemma4:9b or 27b
  • MLX: convert with mlx-lm convert
  • Memory (4-bit): 9B → ~6 GB | 27B → ~18 GB
With 128K context, drop an entire contract, codebase, or long report into one prompt — no splitting required.

Getting the most from Mac hardware

MLX, Apple's framework for fast on-device inference

MLX: optimized for Apple Silicon

MLX is Apple's framework designed around the unified memory architecture of Apple Silicon.

Why it matters

  • Unified memory: CPU and GPU share one pool — no VRAM ceiling
  • A MacBook Pro with 48 GB can run 70B models that wouldn't fit on a 24 GB GPU
  • Metal GPU delivers 2–5x speedup over CPU-only

Common commands

  • pip install mlx-lm
  • mlx_lm.generate --model Qwen/Qwen3-27B-MLX
  • LM Studio uses MLX under the hood on Apple Silicon
Qwen3 27B runs at 35–45 tok/s on a MacBook Pro M4 Pro (48 GB) — fast enough to read alongside.

From models to actions: local AI agents

The real power comes when a model pairs with tools — that turns a chatbot into an agent that can take actions.

How agents work

  • A system prompt describes available tools
  • The model responds with a tool call instead of text
  • Your code runs the tool and feeds the result back

A local agent stack

  • Ollama serves models with built-in function calling
  • MCP — standard way to connect tools
  • LangChain / CrewAI for multi-step workflows
"Find the Q3 sales report and email it to the team" → search_files() → send_email() — all on your infrastructure.

GitHub Copilot with a local model

Setup

  • Install GitHub Copilot and Copilot Chat in VS Code
  • Run a local model server — Ollama or LM Studio
  • Point Copilot at your local, OpenAI-compatible endpoint

Example config (Ollama)

{
"models": [{
  "title": "Qwen3 27B",
  "provider": "ollama",
  "model": "qwen3:27b"
}]
}
Tip: Use a smaller model for autocomplete (Mistral 7B) and a larger one for chat (Qwen3 27B). Copilot can use both.

The local approach
